# 模拟核心整理与缺陷审查（2026-09-09）

## 本轮已落实

- `Simulation` 不再引用 Godot、`RTS.Core` 或 `RTS.World`。玩家科技与敌我关系通过 `ISimulationRules` 注入，游戏端由 `SimManager` 适配原有判断。规则接口实现仍读取宿主的确定性状态，并非整个战斗系统已完全脱离节点。
- `SimWorld.SyncRoot` 支持注入；游戏启动和重置都传入原来的 `WorldLock`。无参数移动入口使用实体所属世界，独立测试不再需要假的 SimManager。
- 寻路调试日志通过可选 `DiagnosticSink` 输出；游戏端用 `SIM_PATH_LOG=1` 开启 Debug 日志并排到主线程。关闭时不构造调用参数字符串。日志不纳入哈希、不驱动游戏规则。
- 修复短路径冷却到期后无限重新冷却的问题；冷却到期实际重新寻路。普通 A* 重算同时更新 `PathBuildDistSq`，使无进展判断基于本次路径起点。
- 配置加载完成且校验通过后才标记成功。失败清空部分数据，允许重试；目录缺失、资源加载失败明确抛错。`LoadAll` 支持配置目录参数，默认路径不变。
- 性能探针开关在初始化/重置时读取，移除每个系统每 tick 的环境变量查询；清除重复的旧 tick 注释块。执行顺序保持不变。
- 本地 CI 使用脚本所在目录定位项目，可传 Python/Godot 路径。默认验证本项目的真实模拟；Arena 检查通过 `-ArenaRoot` 显式启用，并明确报告跳过项。
- 静态扫描增加模拟层反向依赖检查，防止再次引入 Godot/宿主依赖。该脚本仍是启发式检查，不能代替线程安全审计。

## 锁步边界

保留 20Hz 定点步长、随机数、实体遍历顺序、指令协议、指令排序以及游戏世界锁。寻路缺陷修复会改变受影响场景的模拟结果；所有联机端需使用相同版本，旧版本回放的哈希兼容性未验证。双世界测试证明覆盖场景中的一致性，不代表已穷尽所有技能、长局和网络时序。

## 已识别、尚未修改的问题

1. **长回放丢失早期输入（代码路径确认）**：`LockstepManager.CleanupOldTicks` 会清除超过 `MaxHistoryTicks=2000` 的 `HistoryArchive`，`SaveReplayToFile` 却直接用该缓存保存整局，同时保存从开局累计的哈希。超过约 100 秒后，导出的回放可能缺少开局输入。应将完整录制流与网络重发窗口分开，并增加超过 2000 Tick 的录制/重放测试。
2. **回放默认长度推断错误（代码路径确认）**：`ReplayAutoVerify.LoadAndStart` 用刚被清空的 `ReplayTickHashes.Count` 推算总时长，通常回退到 600 Tick。应读取文件中已录制的末帧，而不是运行期校验结果列表。
3. **旧协议判别歧义（代码路径确认）**：`NetAction.TryDeserialize` 用第一个整数是否为 2 判别新版；旧格式的 PlayerID=2 与协议版本冲突。应使用明确的 magic/version 或入口协商，配合兼容性测试后统一升级，不能单端修改线协议。
4. **状态哈希覆盖不足（代码路径确认）**：例如 `EarthCoreBoostedNodes` 和 `AppliedEarthCores` 仅混入数量，没有混入成员 ID；相同数量、不同内容可能无法及时发现差异。加强哈希需要同时考虑回放版本迁移。
5. **植物吸血语义待核实**：当前吸血代码位于死亡分支，仅击杀时触发，注释则描述攻击吸血。本轮保留既有规则，需结合玩法设计确认是否应改为每次有效伤害触发。
6. **线程屏障粒度待对拍**：模拟线程一轮可执行多个 tick，之后才派发主线程队列；延迟生成等操作对后续帧可见的时点，可能受一轮执行数量影响。应增加不同渲染帧率/追帧负载下的双客户端测试后再调整调度。
7. **Godot 无头退出资源泄漏**：本轮 AI 冒烟复现了资源释放报错；尚未确认是现有批量渲染、退出顺序还是引擎无头实现的问题。

## 运行

在 PowerShell 中从项目根目录执行：

```powershell
./Tools/run_ci.ps1 -PythonPath <python可执行文件> -GodotPath <GodotMono控制台可执行文件>
```

已还原依赖时可加 `-NoRestore`。不传 `-GodotPath` 会明确跳过 Godot 冒烟检查。`SIM_PROFILE=1` 开启性能统计；`SIM_PATH_LOG=1` 开启 Debug 寻路日志，均在启动或重置时生效。
